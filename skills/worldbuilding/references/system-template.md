# 体系模板（System Template）

新建世界体系档案时使用此模板，路径约定：`worldbuilding/systems/{system-name-kebab}.md`。**体系**指世界里有规则、有结构、有影响的抽象系统：魔法、政治、技术、宗教、经济、军事、社会……

> 一条体系 = 一套规则 + 局限 + 代价 + 实践者 + 社会影响。不要把"剧情设定"塞进体系里——剧情归弧线，体系归体系档案。

每种体系类型需要回答的核心问题不同，详见 `world-element-types.md`。这里只给通用 frontmatter 与文件结构。

## frontmatter 字段表

| 字段 | 必填 | 类型 / 允许值 | 说明 |
| --- | --- | --- | --- |
| `name` | 是 | 字符串 | 体系名称；可带括号副标题 |
| `type` | 是 | `magic` \| `political` \| `technology` \| `religion` \| `economic` \| `military` \| `social` \| `education` \| `other` | 体系类型。决定 `world-element-types.md` 中的提示清单 |
| `prevalence` | 是 | `universal` \| `common` \| `uncommon` \| `rare` \| `secret` | 普及程度。`secret` 表示该体系被刻意隐藏或仅极少数人知晓 |

## YAML 示例

```yaml
---
name: "燃烬术"
type: magic
prevalence: rare
---
# 燃烬术：以活物之"烬"——记忆、寿命、情感碎片——为燃料的施法体系。
# 仅北境残余术士掌握，且代价极高。
```

```yaml
---
name: "六镇议会"
type: political
prevalence: common
---
# 北境六镇轮流主持的合议机构。每镇执政两年，六年一轮。
```

## 文件结构

```markdown
## 概述

本体系是什么、在世界中扮演什么角色。一段话讲清"这是什么 + 为什么重要"。

## 规则与限制

体系怎么运作、能做什么、不能做什么、代价是什么。**写得越具体越好**——硬限制是体系最值钱的部分：

- 能量/资源从哪里来
- 谁可以使用
- 每次使用的代价（体力、寿命、记忆、材料、关系）
- 硬边界（不能复活死者、不能凭空造物、不能改变过去等）
- 灰色地带（理论上可以但极少人做到）

## 历史

体系如何被发现/发明/演化。关键的历史节点（哪些事件把体系推到今天这个形态）。只写与剧情相关的。

## 实践者

| 维度 | 内容 |
| --- | --- |
| **社会地位** | 被尊崇 / 被惧怕 / 被边缘化 |
| **门槛** | 血统、训练、考试、机缘、契约 |
| **组织** | 行会、宗派、学院、隐秘团体 |
| **代表角色** | kebab-case 角色 id 列表——通常打 `magic-user` 之类标签 |

## 社会影响

体系如何影响日常生活、文化、政治、冲突——二级与三级涟漪。例如：

- 一种**魔法体系**会改变宗教、阶级、战争形态
- 一种**政治体系**会影响法律、税收、对外关系
- 一种**经济体系**会决定哪类人富裕、哪类人赤贫

## 与其它体系的交叉

魔法 vs 宗教 / 技术 vs 魔法 / 经济 vs 政治——列出与本体系耦合最深的其它体系档案 kebab id。
```

## 使用说明

- **不要让一个体系文件覆盖太多领域**。如果"政治 + 经济 + 军事" 写在一起就是大陆设定而不是体系；拆成三条独立档案。
- **`prevalence: secret` 要谨慎使用**：被标记为 `secret` 的体系不进入 `_index.md` 的常规列表；如需在公开索引中隐藏，请同时在 `_index.md` 用 frontmatter 字段控制可见性。
- **与角色档案的关联**：实践者列表里的角色应同时在角色档案的 `tags` 里加对应标签（如 `magic-user` / `court-official`），便于双向检索。
- **硬限制最重要**：写不出来硬限制时，问自己"主角用这套体系能解决一切问题吗？"——如果答案是肯定的，就再补一两条限制。
- **校验联动**：每次新增/修改体系后跑 `story reindex .` 与 `story validate .`；后者会校验 `type` 是否在枚举内。
